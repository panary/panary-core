* **Update**: Der Support-Log-Export gibt den **Event-Namen** wieder heraus — `event` steht jetzt auf der Allowlist `SAFE_LOG_FIELDS` ([`apps/api-edge/src/utils/log-bundle.ts`](../../apps/api-edge/src/utils/log-bundle.ts)). 🚨 Die Lehre ist allgemeiner als das Feld: Eine Auslassung in einer Allowlist ist nicht „ein Feld fehlt", sondern eine **falsche Antwort auf eine Suche**. Am 2026-09-12 lieferte `grep 'sync.conflict.apply_failed'` über den Export 0 Treffer (keine einzige von 7380 Zeilen trug ein `event`-Feld) und wurde als „die Zeile wurde nie geschrieben" gelesen — sie stand da, nur ohne ihren Namen; auffindbar war sie über `message`. Damit war jede Verifikation der Form „Event `x.y` darf nur auftreten, wenn …" über den Export unbeantwortbar, obwohl das die Form ist, in der Runbooks und Issues eine Logzeile adressieren (Befund aus [#293](https://github.com/panary/panary-core/issues/293)). Unbedenklich ist der Wert, weil er aus dem Code stammt und nicht aus den Daten: gemessen über `apps/` + `libs/` 220 verschiedene Namen, alle feste Zeichenketten, die einzige Interpolation setzt einen Enum-Wert ein. Dazu die erste Spec für `scrubLogEntry`, die **beide** Richtungen festnagelt — was durchkommt und was draußen bleibt (`businessContext`, `requestData`, `errorStack`, `validationErrors`).
