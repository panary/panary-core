* **Fix**: Bestands-Edges, deren einziges Verwaltungskonto archiviert ist, bekommen ihren Zugang ohne DB-Eingriff zurück. Die Migration [`20260912160000_reactivate_locked_out_owner.ts`](../../apps/api-edge/migrations/20260912160000_reactivate_locked_out_owner.ts) schaltet archivierte `tenant:owner`/`platform:owner`-Konten auf `ACTIVE` — 🚨 **nur wenn kein anmeldefähiges Konto mit `users: MANAGE` mehr existiert**; die Bedingung ist der Kern, nicht die Aktion, sonst wäre `ARCHIVED` für die mächtigste Rolle wertlos. Geheilt wird ausschließlich, was nie in die Cloud gepusht wird (`SYNC_PUSH_BLOCKED_USER_ROLES`): Bei einem archivierten `tenant:technician` trägt der Status echte Information, bei `REJECTED` steckt eine menschliche Entscheidung dahinter — beide bleiben unberührt. `updatedAt` wird mitgesetzt (sync-neutral, die Konten verlassen den Edge nie), `down()` ist ein dokumentiertes No-op, und die Reaktivierung schreibt eine Zeile ins Boot-Log. ⚠️ Rollen-Literale ohne Domain-Import, weil Migrationen als Assets mit `--bundle=false` transpiliert werden und ein Auflösungsfehler die Migration **still** ausfallen ließe — gelockt per Test gegen `USER_MANAGE_ROLES`/`SYNC_PUSH_BLOCKED_USER_ROLES`, dazu das echte SQL gegen eine In-Memory-SQLite (Idempotenz, fehlende Tabelle, fehlende Spalte).
