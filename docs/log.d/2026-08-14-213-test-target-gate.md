* **Fix**: Zwei explizite `test`-Targets entfernt (`businessdays-aggregator`, `orders-feature-pos-order-dialog`) — sie verhinderten das Test-Caching **vollständig**. Beide deklarierten `@nx/vite:test`, denselben Executor, den das Plugin ohnehin nutzt, und für den es **kein `targetDefaults`** gibt: Das Target erbte damit weder `cache: true` noch `inputs`. Gemessen am Aggregator (162 Tests, 17 Dateien): unveränderter zweiter Lauf → Tests laufen erneut; nach dem Entfernen → „Nx read the output from the cache instead of running the command for 1 out of 1 tasks". Die beiden Projekte haben ihre Tests also bei jedem CI-Lauf neu ausgeführt. Testzahlen unverändert (162 bzw. 38), die coverage-`outputs` bringt das inferierte Target selbst mit ([panary/panary-core#213](https://github.com/panary/panary-core/issues/213)).
* **Fix**: `test` ins Überschreibungs-Gate aufgenommen und damit eine Fehleinschätzung aus [#210](https://github.com/panary/panary-core/issues/210) korrigiert. Dort war `test` mit der Begründung „5 Fälle im Bestand, null echte Funde, fünf Fehlalarme" ausgenommen worden — tatsächlich waren zwei der fünf echte Drift. Der Fehler lag nicht in der Zahl, sondern in der Annahme, ein *konfiguriertes* Target sei damit auch ein *gewolltes*: `outputs` und `configFile` sahen nach Absicht aus, waren aber Generator-Erbe. **Ein explizites Target daran zu messen, wie viel darin steht, unterscheidet Absicht nicht von Ballast.**
* **Creation**: Statt `test` pauschal freizugeben, führt das Gate jetzt eine **Executor-Allowlist** je Target-Name (`test` → `@angular/build:unit-test`). Die drei Angular-Apps fahren bewusst den Angular-Test-Builder und cachen korrekt (dafür existiert ein `targetDefaults`-Eintrag); eine vierte Angular-App muss deshalb nichts quittieren, während ein `@nx/vite:test` weiterhin anschlägt. Die Allowlist gilt **je Target-Name**, nicht global — sonst öffnete eine Ausnahme für `test` versehentlich auch `lint`; ein Spec-Fall nagelt das fest. Neu ist außerdem, dass das Gate seine **Lücken bei jedem Lauf mitdruckt** („Ungeprueft: build. Erlaubte Ausnahmen — test: @angular/build:unit-test"): Eine Abdeckung, die man nur im Quelltext nachlesen kann, wird überschätzt.
