* **Fix**: `api-edge` wird typgeprüft — bis dahin gar nicht. `nx run api-edge:typecheck` antwortete „Cannot find configuration for task", weil das `@nx/js/typescript`-Plugin sein Target aus einer `tsconfig.json` ableitet und `apps/api-edge/` als einzige TS-schwere App keine besaß. Die CI fährt `nx affected -t lint,test,typecheck,build` und überging das Projekt schweigend; acht Tage lang las sich „grün, 83 Projekte" wie eine Zusage über den Workspace, während die 208 TS-Dateien der Edge-App nicht darin vorkamen. Ein fehlendes Target ist unsichtbarer als ein rotes: Es meldet sich nicht, es macht nur die Gesamtzahl kleiner ([panary/panary-core#202](https://github.com/panary/panary-core/issues/202)).
* **Fix**: Zwei Konfigurationsdefekte darunter behoben, beide an der Wurzel statt am Symptom. `tsconfig.spec.json` erbte von `tsconfig.app.json` mit `rootDir: ./src`, ihre `include` zieht aber `vitest.config.mts` aus dem Projekt-Root herein → `TS6059`, bevor eine einzige Spec geprüft wird (dieselbe Klasse wie das `TS5069` von #110). Sie erbt jetzt von der neuen `tsconfig.json`, womit `rootDir` wie überall sonst der Workspace-Root ist — was ohnehin nötig ist, weil die Specs `@panary/*` aus `libs/` importieren. Aus demselben Grund verliert `tsconfig.app.json` ihr `rootDir: ./src` (146× `TS6059` unter `tsc --build`); **die Build-Ausgabe bleibt davon unberührt** — nachgemessen, nicht angenommen: alle 738 Artefakte unter `dist/apps/api-edge` sind vorher wie nachher byte-identisch.
* **Fix**: Die `include` der spec-Config kannte nur `src/**`, `vitest.config.mts` lädt aber `{src,test,tests}/**` — **25 Dateien** unter `test/` liefen in jedem Testlauf mit, ohne je typgeprüft zu werden. Jetzt erfasst; drei der vier gefundenen Bestandsfehler saßen genau dort. Alle vier behoben (Bestand: keine Baseline, [ADR 0022](../adr/0022-format-gate-ohne-base.md)) — der Produktivcode war bereits sauber, der blinde Fleck hat also keine Schuld verdeckt, sondern nur nicht verhindert, dass sie entsteht.
* **Update**: [Nx-Typecheck-Target](../infrastructure/nx-typecheck-target.md) — Stand auf 84 Projekte, neuer Abschnitt zum blinden Fleck und eine Abdeckungsprüfung, die die Target-Liste gegen die Projektliste hält. Die Zahl allein beantwortet die Frage nicht, die man ihr stellt.
