* **Fix**: Der Remote-Cache-Retry im CI-Schritt „Lint, Test, Typecheck & Build (affected)" ([`ci.yml`](../../.github/workflows/ci.yml)) startet nur noch bei einer echten Fehlerzeile von Nx ([#411](https://github.com/panary/panary-core/issues/411)). Bisher genügte `grep -qiE 'remote cache'`. Das traf auch die Kennung `[remote cache]` jedes normalen Treffers: Ein roter Lauf mit Treffern wäre ein zweites Mal ohne Cache gelaufen, mit der falschen Warnung „Remote-Cache nicht nutzbar". 401 und ein unerreichbarer Server wurden dagegen nie erkannt, denn ihre Meldungen enthalten die Wörter gar nicht. Gemessen mit nx 22.7.12 gegen einen Wegwerf-Server: 5xx ergibt `Misconfigured remote cache endpoint: …`, 401 ergibt `Unauthorized: <Antworttext>`, ein unerreichbarer Server ergibt `Failed to send request: …`. Beim GET steht die Zeile hinter dem `NX`-Banner, beim PUT am Zeilenanfang. Das neue Muster trifft in vier echten Logs genau die zwei echten Fehlerzeilen und keinen der 132 `[remote cache]`-Treffer. Mutationsprobe auf sieben Fixtures: Das alte Muster verfehlt vier davon, Muster ohne `Unauthorized` zwei, Muster ohne Zeilenanfang eine. Zur Ursache der 500: Nur ein **GET**, der 500 statt 404 liefert, erzeugt das Bild aus der CI. Nx meldet dann „Successfully ran target", ohne etwas ausgeführt zu haben, und bricht ab. Bei einem PUT-Fehler liefe der Task vorher. Der Server beantwortet also einen Cache-Miss mit 500. Die Klärung am Host und die Runbook-Korrektur laufen über [panary/panary-cloud#629](https://github.com/panary/panary-cloud/issues/629).
