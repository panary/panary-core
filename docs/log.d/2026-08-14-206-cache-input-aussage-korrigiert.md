* **Update**: [Lib-Vitest-Test-Target](../guides/lib-vitest-test-target.md) — die Cache-Input-Aussage aus [#206](https://github.com/panary/panary-core/issues/206) richtiggestellt. Dort stand, das explizite `"lint": { "executor": "@nx/eslint:lint" }` habe die projektlokale `eslint.config.mjs` nicht in den Inputs gehabt, eine Änderung daran invalidiere den Cache also nicht. Das trifft nicht zu: Die Inputs begannen mit `default`, und `default` ist in `nx.json` als `{projectRoot}/**/*` definiert — die Datei liegt im projectRoot. Am expliziten Target nachgemessen (`libs/shared/ui-notifications`, alter Stand wiederhergestellt): unverändert → Cache-Treffer, Änderung an der lokalen `eslint.config.mjs` → echter Lauf, erneut unverändert → Cache-Treffer, zweite Änderung → wieder echter Lauf. Gefehlt haben stattdessen `^default` (Änderungen in Abhängigkeiten) und `externalDependencies: ["eslint"]` (Versionswechsel von eslint) — beide bringt nur das inferierte Target mit. Der Aufräum-Grund bleibt, der belegte Schaden ist ein anderer.
