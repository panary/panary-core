* **Update**: `AuditAction` in [`audit-action.enum.ts`](../../libs/domains/audit-events/domain/src/lib/audit-action.enum.ts) kennt jetzt `EXPORT` — ein Datenexport (Katalog, Belege, DSFinV-K, DSGVO), Kategorie `ACCESS`: Datenabfluss, keine Mutation ([#435](https://github.com/panary/panary-core/issues/435)). Ohne den Wert verwirft `validateData` jedes Export-Event am `enum`-Keyword. Die Spec [`audit-event.schema.spec.ts`](../../libs/domains/audit-events/domain/src/lib/audit-event.schema.spec.ts) validiert ein vollständiges Event über `getValidator` am **String-Literal**; Mutationsprobe mit gestrichenem Wert: rot mit `enum`. In core gibt es keine Label- oder Kategorie-Zuordnung je Aktion, die nachgezogen werden müsste — `AUDIT_RESOURCE_MAP` braucht den Wert nicht, weil die Edge heute nichts exportiert. Die Cloud schreibt die Aktion ab [panary/panary-cloud#695](https://github.com/panary/panary-cloud/issues/695) nach dem Pin-Bump.
